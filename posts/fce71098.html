Qt 安装说明

从 Qt 官网 下载在线安装器（比如 qt-online-installer-windows-x64-4.11.0.exe），运行后根据实际开发需求选择相应的组件进行安装。常见组件及其作用如下表所示：

组件作用必选
Qt SDK 包含 Qt 库及相关开发组件，用于开发 Qt 应用程序。是
MinGWWindows 平台上的 GCC 编译器工具链，用于编译 C/C++ 程序。否（使用 MinGW 工具链时必选）
MSVC 微软 C/C++ 编译器工具链，用于 Windows 平台上的 C/C++ 程序开发。否（使用 MSVC 工具链时必选）
Ninja 高效的构建工具，常与 CMake 配合使用，执行编译和链接，作用类似 Linux 平台的 Make。否
CMake 跨平台构建系统生成工具，用于配置项目并生成构建文件。否（使用 CMake 管理项目时必选）
Qt CreatorQt 集成开发环境，提供代码编辑、项目管理、编译和调试等功能。否（使用 Qt Creator 开发时必选）
Qt Design Studio 用于可视化设计 QML 界面、创建动画和 UI 原型。否

  • 组件说明：

    • MinGW 和 MSVC 二选一即可，通常不需要同时安装；具体取决于选择的 Qt 编译器套件（如下图所示）。
    • CMake 和 Ninja 并非所有项目都必须使用，Qt 项目也可以采用其他构建工具，例如 QMake（不推荐）。
    • Qt Creator 和 Qt Design Studio 是不同工具：前者负责日常编码与调试，后者侧重 QML 界面设计。
    • 如果是初学 Qt，建议安装 Qt SDK、Qt Creator、Qt Design Studio，以及与所选 Qt 套件匹配的编译器。

  • 注意事项：

    • 如果 Qt 在线安装失败并提示错误信息 server replied: Too Many Requests，可以通过安装参数 --mirror 切换镜像源，然后重新安装。
    • 比如切换使用阿里的 Qt 镜像源：qt-online-installer-windows-x64-4.11.0.exe --mirror https://mirrors.aliyun.com/qt。

QML 基础概念

QML 是一种用于描述用户界面及其交互逻辑的声明式语言，开发者可以通过简洁的语法定义界面元素、属性、布局、动画以及属性之间的绑定关系；Qt Quick 则是 Qt 提供的一套用于构建动态、流畅用户界面的技术框架，包含丰富的 QML 类型和相关功能。二者通常配合使用：QML 负责描述界面，Qt Quick 提供构建界面所需的类型和功能，开发者还可以通过 C++ 扩展 QML 类型或实现复杂业务逻辑，从而结合 QML 的界面开发效率与 C++ 的性能优势。

访问外部库或 QML 目录

核心概念

  • QML 导入语句

    • (1) 导入库：import <ModuleIdentifier> [<Version.Number>] [as <Qualifier>]
      • import Namespace VersionMajor.VersionMinor
        • import QtQuick 2.0
        • 版本号说明：
          • 导入 QML 模块时，指定的版本号会被视为最低兼容版本。只要请求的版本号小于或等于模块的实际版本号，即视为兼容
          • 如果不指定版本号，则默认使用当前环境中该模块的最新版本（而在 Qt 6 中，由于支持省略版本号，通常表现为自动关联当前模块的最高可用版本）
          • Qt 各版本号的对应关系如下表所示：
      • import Namespace VersionMajor.VersionMinor as SingletonTypeIdentifier
        • 导入库：
          • import QtQuick.LocalStorage 2.0 as Database
          • import QtQuick.Controls as Cont
        • 使用库：
          • Database { }
          • Cont { }
    • (2) 导入目录中代码：import "<DirectoryPath>" [as <Qualifier>]
      • 导入本地目录：
        • import "./privateComponents"
      • 导入远程目录：
        • import "http://www.my-example-server.com/myapp/mycomponents" as MyComponents
      • 导入注意事项：
        • 模块导入（Module Imports）的优先级高于本地目录导入（Directory Imports）
        • 对于从本地目录导入的 QML 文件，可以直接使用其大写字母开头的文件名（去掉 .qml 后缀）作为组件类型名
        • 在 QML 中，import "<DirectoryPath>" 仅在导入本地目录时有效，若需导入远程目录的 URL，则必须使用带 as 别名的写法（如 import "http://..." as RemoteLib）
    • (3) 导入 JS 代码：import "<JavaScriptFile>" as <Identifier>
      • 导入 JS 代码
        • import "myjs.js" as MyJs
      • 调用 JS 代码
        • MyJs.process()

  • QML 导入路径

    • 当前文件的目录
    • 指定的位置 QLibraryInfo::QmlImportsPath
      枚举值序号路径说明
      QLibraryInfo::PrefixPath0 所有路径的默认前缀。
      QLibraryInfo::DocumentationPath1 安装时的文档路径。
      QLibraryInfo::HeadersPath2 所有标头的路径。
      QLibraryInfo::LibrariesPath3 已安装库的路径。
      QLibraryInfo::LibraryExecutablesPath4 运行时库所需的已安装可执行文件的路径。
      QLibraryInfo::BinariesPath5 已安装的 Qt 二进制文件（工具和应用程序）的路径。
      QLibraryInfo::PluginsPath6 安装的 Qt 插件的路径。
      QLibraryInfo::QmlImportsPath7 要导入的已安装 QML 扩展的路径。
      QLibraryInfo::Qml2ImportsPath-QmlImportsPath 该值已被弃用。请改用 QmlImportsPath。
      QLibraryInfo::ArchDataPath8 通用依赖于架构的 Qt 数据的路径。
      QLibraryInfo::DataPath9 通向独立于架构的通用 Qt 数据的路径。
      QLibraryInfo::TranslationsPath10Qt 字符串翻译信息的路径。
      QLibraryInfo::ExamplesPath11 安装时示例的路径。
      QLibraryInfo::TestsPath12 已安装的 Qt 测试用例的路径。
      QLibraryInfo::SettingsPath100Qt 设置的路径。不适用于 Windows 系统。
    • QML_IMPORT_PATH 环境变量指定的路径
    • 资源内的 qrc:/qt-project.org/imports 路径。
    • 资源内的 qrc:/qt/qml 路径（自 Qt 6.5 起支持）。
