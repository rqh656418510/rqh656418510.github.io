CentOS 7 使用 llama.cpp 部署本地大模型

发表于 2025-11-09 更新于 2026-11-12 阅读次数： 评论数： 本文字数： 4.6k 阅读时长 ≈ 4 分钟

前言

本文将在 CentOS 7.9 基础上介绍 llama.cpp 的编译安装与大模型的本地部署，默认采用 CPU 推理方式，不依赖 NVIDIA 显卡驱动和 CUDA 环境。如果需要使用 GPU 推理，则需要在编译时启用 llama.cpp 的 CUDA 后端，并确保 NVIDIA 显卡驱动、CUDA Toolkit、CUDA Runtime 以及 GPU 硬件架构之间满足版本兼容要求。例如，较新版本的 CUDA 通常要求更高版本的 NVIDIA 显卡驱动（部分 CUDA 12.x 版本需要 525 或更高版本，具体取决于 CUDA 小版本）。需要注意，CentOS 7.9 默认的 G++ 版本是 4.8.5，如果 CUDA 的版本也比较老旧，可能无法满足最新版本 llama.cpp CUDA 后端的编译要求。因此，如果希望在老旧环境中使用 GPU 推理（加速），通常需要升级 NVIDIA 显卡驱动和 CUDA 工具链，并选择与之兼容的 llama.cpp 版本。

准备工作

安装 CMake

  • llama.cpp 官方采用 CMake 作为项目构建工具，因此在编译源码之前，需要提前安装 CMake，并确保其版本满足当前 llama.cpp 的构建要求。
  • 建议从 CMake 官方渠道安装较新版本，避免因 CMake 版本过低导致项目配置或编译失败。
  • CMake 的安装步骤，可参考 《Linux 安装 CMake 3 》。

安装 OpenSSL

切换 G++ 版本

CentOS 7.9 自带 G++ 4.8.5，不建议直接用其编译当前最新版本的 llama.cpp 源码；即使关闭 CUDA、只编译 CPU 推理版本，也不能保证编译通过。因为 llama.cpp 的 CPU 后端虽不依赖 CUDA，但仍使用较新的 C++ 特性和编译器能力，而 G++ 4.8.5 对现代 C++ 标准支持不足。推荐解决方案是：无需升级 CentOS 7.9，也无需升级系统自带的 G++ 版本，而是额外安装新版本 G++（如 G++ 9 或更高版本），并通过环境变量切换 C++ 编译器；CentOS 7 可尝试使用 SCL Devtoolset 来切换 C++ 编译器环境。

安装 SCL 软件源

  • 安装 SCL 软件源
  • 由于 CentOS 7 的 SCL 软件源已经停止维护，原来的软件源地址不可用，因此需要更换为阿里云的 SCL 软件源
  • 清理并构建 YUM 缓存

特别注意

  • CentOS 7 已于 2024 年 6 月 30 日结束生命周期，SCLo 仓库也受到影响，因此需要使用阿里云的 SCL 软件源。
  • 上面配置阿里云的 SCL 软件源时，暂时使用了 gpgcheck=0，这仅用于排查仓库签名问题；正式使用建议恢复 GPG 校验并配置可信密钥。

安装 Devtoolset

Devtoolset 的作用

  • Devtoolset 是 Red Hat / CentOS 提供的软件开发工具集，主要用于在不升级系统原有编译器的情况下，安装和使用较新版本的 GCC、G++ 等开发工具。
  • 例如：CentOS 7 默认的 G++ 版本是 4.8.5，通过安装 Devtoolset，可以额外使用 G++ 9，而不影响系统原有的 G++ 4.8.5。

检查 AVX2 指令集

  • 检查 CPU 是否支持 AVX2 指令集，如果输出结果包含 avx2，则后面可以考虑编译 llama.cpp 的 AVX2 优化版本

AVX2 指令集的作用

  • AVX2（Advanced Vector Extensions 2）是 Intel 提供的一种 CPU SIMD（单指令多数据）指令集扩展技术，支持使用 256 位寄存器同时处理多个数据，从而提高数据并行计算效率。
  • 对于 llama.cpp 等大模型推理程序，AVX2 可以加速矩阵运算、向量计算等操作，提升 CPU 推理性能，减少模型计算耗时。

  • G++：建议准备 G++ 9 或更高版本

硬件规划

下表是使用 CPU 推理时的粗略硬件资源规划，实际硬件资源占用还取决于上下文长度、模型架构和 KV Cache 配置

特别注意

  • 物理内存除了需要容纳模型权重，还需要为 KV Cache、推理过程和操作系统预留内存空间。
  • CPU 核心数越多，不一定意味着推理速度越快，还需要考虑 CPU 架构、CPU 主频和内存带宽。
  • 强烈建议优先关注 AVX2 指令集支持、物理内存容量和内存带宽，其次再考虑 CPU 核心数。
  • 如果服务器的 CPU 核心数较少，或者没有 AVX2 指令集，即使 llama.cpp 能够成功运行模型，生成速度（Token 吞吐量）也可能比较慢。

选择模型

个人电脑（CPU、内存受限）通常只能部署量化后的蒸馏版本（如下表所示），比如 7B、32B 的本地量化版本。llama.cpp 官方推荐使用 GGUF 格式的模型，模型资源可以从 Hugging Face 查找，下载模型时优先选择已经转换为 GGUF 格式的模型，而不是直接下载 Hugging Face 上的原始 safetensors 权重。

DeepSeek-R1-Distill-Qwen-1.5BQwen2.5-Math-1.5B1.5BQ4_K_M 基于千问 Qwen2.5-Math-1.5B 蒸馏的轻量级模型，适合资源受限场景
DeepSeek-R1-Distill-Qwen-7BQwen2.5-Math-7B7BQ4_K_M 基于千问 Qwen2.5-Math-7B 蒸馏，效果与资源需求较均衡
DeepSeek-R1-Distill-Llama-8BLlama-3.1-8B8BQ4_K_M 基于 Llama 3.1-8B 蒸馏
DeepSeek-R1-Distill-Qwen-14BQwen2.5-14B14BQ4_K_M 基于千问 Qwen2.5-14B 蒸馏，推理能力较强，对内存要求较高
DeepSeek-R1-Distill-Qwen-32BQwen2.5-32B32BQ4_K_M 基于千问 Qwen2.5-32B 蒸馏，推理能力较强，适合较高配置的硬件环境
DeepSeek-R1-Distill-Llama-70BLlama-3.3-70B-Instruct70BQ4_K_M 基于 Llama 3.3-70B-Instruct 蒸馏，模型规模较大，对硬件资源要求较高

模型版本说明

  • 1.5B、7B、14B、32B 这四个 Qwen 蒸馏模型均使用 DeepSeek-R1 生成的样本进行微调，基础架构分别来自阿里巴巴的 Qwen2.5-Math 和 Qwen2.5 系列。
  • Llama-8B 基于 Meta 的 Llama 3.1-8B-Base 蒸馏而来；Llama-70B 则基于 Meta 的 Llama 3.3-70B-Instruct 蒸馏而来。

特别注意

使用 llama-cli 或 llama-server 从 Hugging Face 下载模型时，llama.cpp 必须启用 HTTPS 支持。在编译 llama.cpp 源码时，需要添加 -DLLAMA_OPENSSL=ON 参数，并确保系统已安装 OpenSSL 开发库（如 openssl-devel），且 OpenSSL 版本满足当前 llama.cpp 的最低版本要求。需要注意的是，仅指定 -DLLAMA_OPENSSL=ON 并不意味着 llama.cpp 一定能够启用 HTTPS，如果 OpenSSL 版本过低，CMake 的版本兼容性检查仍可能失败，导致最终编译生成的 llama.cpp 程序不支持 HTTPS。如果无法解决 llama.cpp 的 HTTPS 支持问题，可以使用 Hugging Face CLI 单独下载所需的 GGUF 模型文件到本地，然后通过 llama-cli 或 llama-server 指定本地模型文件路径（-m 参数）启动模型，无须依赖 llama.cpp 的 HTTPS 下载功能。
