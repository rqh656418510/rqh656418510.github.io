DSH 免费模型任意用：dsh-our-free-model 插件上手介绍

发表于 2026-11-03 阅读次数： 评论数： 本文字数： 5.1k 阅读时长 ≈ 5 分钟

插件介绍

dsh-our-free-model 是一个为 DSH（DeepSeek Harness） 设计的开源插件，核心定位可以概括为一句话：把散落在各大平台的免费模型额度，聚合成一个免登录、免 API Key 的模型池，直接嵌进 DSH 的模型选择器里。它不训练模型、不自建推理服务，全部工作在本地完成；插件主体是纯 JavaScript 适配层，不含推理实现，也没有 NPM 运行时依赖（DSH 侧的 peer 依赖由宿主提供），采用 MIT 协议。项目由 Ebony-Vinyl 维护，曾在 GitHub JavaScript 周榜拿下第一。桌面端另有 EAC 渠道，登录 GitHub 并给仓库点 Star 即可解锁。

核心作用

  • 零门槛扩展 DSH 的模型选择器

    • 装上插件并重启 DSH 后，输入框旁的模型选择器里会多出一个 “Our Free Model” 分组。
    • 分组内直接列出可用模型，点一下就能聊，不需要注册、登录或填写任何 API Key。
    • 典型模型包括 DeepSeek V4.1 Flash、Kimi K3、GLM 5.3 Flash、MiMo V2.6 等。

  • 聚合多条免费额度来源

    • 插件接入的不止一两家渠道。
    • 聚合来源包括 OpenCode 的 Zen 网关、Kilo AI 的公共网关，以及 LobsterAI、TRAE、Qoder / Qoder 中国版、Cline、Loomy（讯飞）、Raccoon（商汤）、MiniMax Code、ZCode、Gemini 共 10 家平台的账号渠道。
    • 账号渠道需要各自登录一次，凭据写入宿主凭据库，模型统一出现在模型选择器里。
    • OpenCode 和 Kilo 两条 “匿名通道” 尤其关键：前者只需把请求补齐成官方客户端的样子即可使用，后者无需任何认证头，直接就能调通免费模型。

  • 按 “你这台机器能不能连上” 来展示模型，而不是堆列表

    • 模型清单随上游刷新，可用性按当前网络出口的真实结果归置：自动探测已关闭，状态主要从真实回合学习，也可以在设置页手动 “重新探测可用性”。
    • 被地区限制的模型单独归入 Our Free Model · region-limited 分组，网络变化后点一次 “重新探测可用性” 即可在两个分组之间迁移。
    • 被网关明确拒绝路由的模型收在设置页 “不在选择器中” 一栏（附拒因与探测时间），不干扰日常选择；上游 5xx、429、超时与断网不当作模型不可用。
    • 这和 “列一百个、能用的没几个” 的免费聚合站是相反的思路。

  • 思考档位真实下发到上游

    • 对于声明了思考档位的模型（如 DeepSeek V4.1 Flash、GLM 5.3 Flash），插件会给出该模型自己声明的档位菜单（Off / Low / High / Max 等），选中值原样作为 reasoning_effort 发给上游，而不是只换个图标；没有声明关闭档的模型就只列其余档位（GLM 5.3 Flash 即无 Off 档）。
    • 对于没有档位菜单的模型（如 MiMo V2.6），则走预算阶梯（Light / Balanced / Deep）。
    • 关不掉思考的模型，三档整体翻倍。

  • 附带一套实用的本地管理面板

    • 插件自带用量看板（Token 热力图、总量曲线、按模型汇总）。
    • 提供本地转发开关（可复制 Base URL 和 API Key，供 Claude Code、Codex 等不认 DSH 的工具调用同一批模型）。
    • 提供插件设置（自动刷新间隔、默认输出上限、出口 IP 与国家）以及一键升级等功能。
    • 此外还提供一个可独立运行的本地服务（仍在开发中，安装制品尚未发布）：不依赖 DSH 宿主，默认使用 ~/.our-free-model 和端口 18900，拥有自己的 API Key 和网页管理界面。

免费额度说明

  • 免费额度由上游单方面提供，按会话限速，短时间内打满会返回 429，额度政策也可能随时变更，并不等于不限量。
  • Kilo 免费池的模型卡明确提示 prompt 可能被上游记录并用于改进服务；请勿通过免费车道发送密码、密钥、个人信息或商业机密。

源码安装方式

dsh-our-free-model 有多种安装方式，其中通过源码安装包括以下两种方式：

  • (1) 不安装 DSH，直接跑独立本地服务（纯源码启动，服务仍在开发中）
  • (2) 作为 DSH 插件挂载源码目录（需要依赖 DSH 宿主）

环境要求

  • Node.js 版本符合仓库 Engines 要求（README 要求 ^22.19.0 || >=24.0.0）。
  • DSH 内核需在仓库声明的适配范围内（README 标注 0.1.7-rc.1，package.json 的 peerDependencies 允许 0.2.0-rc.1）。

独立服务启动

通过源码单独启动 dsh-our-free-model 的 HTTP 服务。该服务目前仍在开发中，安装制品与 Release 尚未发布，只能从完整源码仓库运行（不能只复制该目录，也不能作为 NPM 包单独安装）。默认情况下，该服务会使用 ~/.our-free-model 作为数据目录，并监听 18900 端口（端口被占用时会自动顺延到下一个可用端口）。

  • 拉取源码
  • 启动服务

常用启动参数：

  • --port 18900 指定端口，0 则表示让系统自动分配端口
  • --data-dir /path 或环境变量 OFM_HOME=/path 指定数据目录
  • --lan 开启局域网推理（默认关闭，用独立 LAN Key）
  • --lan-port 18901 指定 LAN 端口（默认 0 表示自动分配，单独使用只保存端口、不启用中继）
  • --no-lan 关闭局域网推理
  • --probe 已停用（仅为兼容保留，不会发送探测请求）
  • --no-refresh 跳过启动刷新与周期任务（账号渠道的登录、续期与自动签到不受影响）

服务启动后终端会打印：

  • 一次性管理页面链接（10 分钟有效，浏览器打开后可以进入控制台页面）
  • 实际 API 地址：http://127.0.0.1:<端口>/v1
  • Key 文件位置：<数据目录>/settings.json 里的 forwardKey 字段（不直接打印 Key）

特别注意

  • 以独立服务启动 dsh-our-free-model 时，不会读取 DSH_HOME 目录，并且和 DSH 插件数据目录默认隔离。
  • 同一数据目录只能起一个 dsh-our-free-model 实例，异常退出残留的 service.lock 文件一般会自动回收（Windows / Linux 在确认旧进程退出后回收），仍残留时先确认旧进程退出了再删除。
  • 验证服务

浏览器访问 http://127.0.0.1:18900/#login=xxxxx，其中 xxxxx 为登录密钥，可以从启动输出的日志信息中获取。若能显示以下界面，则说明启动成功。

插件挂载源码目录

如果想在 DSH 里直接使用 dsh-our-free-model，而不是单独启动 HTTP 服务，可以将 dsh-our-free-model 的源码目录作为 DSH 插件挂载（需要依赖 DSH 宿主）。安装需要环境变量 PATH 上有 pnpm，因为 dsh plugin 子命令会将参数转发给 pnpm。

  • DSH 插件挂载
  • 重启 DSH 应用

插件安装完重启 DSH 一次，如果输入框模型选择器里出现 Our Free Model 分组，则说明 dsh-our-free-model 安装成功。

NPM 包安装方式补充

  • dsh-our-free-model 除了可以挂载源码目录作为 DSH 插件外，也可以作为 NPM 包插件安装：dsh plugin --profile web add @ebony-vinyl/dsh-our-free-model@2.9.0（版本号以仓库当时发布为准）。
  • 安全提醒： 切勿安装 NPM 上的裸名包 dsh-our-free-model（第三方篡改包），只认 GitHub 仓库源码、官方 Release 的 dsh-our-free-model-<版本>.tgz 或 NPM 包 @ebony-vinyl/dsh-our-free-model。

桌面端安装方式

dsh-our-free-model 在桌面端的安装需要区分 Electron 桌面端（DeepSeek Harness Desktop） 和 DSHEAC AIO 两种宿主，两者的限制和使用方式不同。

Electron 桌面端

Electron 桌面端（DeepSeek Harness Desktop）的 desktop profile 由 Electron 应用独占管理。用 NPM 安装的 dsh 命令行改不了它 —— 执行 dsh plugin --profile desktop add <包> 会被直接拒绝，报错为 profile "desktop" is managed exclusively by the Electron application。这是宿主自身的保护机制，与插件无关。需要使用命令行时，可以用桌面端自带的那个 dsh：先启动一次 Desktop 初始化 profile、完全退出应用，再运行安装目录下的 resources/runtime/cli/bin/dsh（Windows 为同目录的 dsh.cmd），执行 dsh plugin --profile desktop add <包>、list 或 remove <包>，重开应用后生效。也可以走应用内插件管理器：打开 DeepSeek Harness 桌面端，进入「设置 → 插件」页面，在添加插件处填入插件的包名、GitHub 仓库地址或本地目录路径进行安装（本地目录应为真实目录，避免 symlink / junction）。安装后在插件列表中确认 Our Free Model 处于启用状态（安装后通常已自动启用，开关用于停用），重启应用即可生效。

特别注意

切记不要安装 NPM 上的裸名包 dsh-our-free-model，那是第三方篡改包。官方发布的是带 scope 的 @ebony-vinyl/dsh-our-free-model，或使用 GitHub Release 中的 .tgz 文件。

DSHEAC AIO

DSHEAC AIO 是基于 DSH-Desktop-EAC 重构的 Windows（x64）一体化桌面发行版，内置了 Node.js 和 DSH 运行时，无需预装环境。它对插件的安装有更严格的限制：部分 AIO 版本在启动前会执行 profile 闸门检查，限制符号链接（symlink）和目录 junction。如果强行用 link: 依赖或 junction 安装，可能触发 PROFILE_UPGRADE_REQUIRED: offline dependency migration is not yet available 报错。因此，在 DSHEAC AIO 中安装 dsh-our-free-model 应优先选择以下方式：

  • 方式一：通过应用内插件管理器安装（首选）

    • 与 Electron 桌面端类似，在 AIO 的插件管理界面中直接安装，避开 profile 闸门对链接类型的限制。

  • 方式二：本地 tarball 安装（备选）

    • 如果应用内安装不可用，可以使用可信源码打包的 tarball。具体步骤是：
      • (1) 先创建 <DSH_HOME>/profiles/<profile>/vendor/，再在审核过的本仓库目录运行 npm pack --ignore-scripts --pack-destination "<DSH_HOME>/profiles/<profile>/vendor"（也可以把官方发布的同版本 .tgz 放进该目录）；
      • (2) 在 profile 的 package.json 的 dependencies 中加入 "dsh-our-free-model": "file:./vendor/dsh-our-free-model-<版本>.tgz"，然后通过宿主的安装流程解析依赖；
      • (3) 在 dsh.profile.bundles 末尾追加 "dsh-our-free-model"，否则插件不会启用；不要再往 cordis.patch.yml 添加条目，否则会报 duplicate loader entry id。手工复制文件时必须复制完整包（包括 adapter/、src/、locale/、vendor/ 下的资源），只复制入口脚本会导致渠道加载失败。
    • 另外，DSHEAC AIO 的 WebView2 权限策略可能拒绝系统通知授权，这是宿主层面的限制，不影响模型功能本身。
